## Findings

1. **[High] MaxHealth doesn't update on a live birthday resize — fails the M2-03 acceptance criterion ("Height/rank change MaxHealth").** `HealthService.luau:120-139` (`setupCharacter`) only runs from `PlayerService.Ready` and once more after `AppearenceLoaded` (`HealthService.luau:226,238-253`). `AgeService.resizeCharacter` (`AgeService/init.luau:109-132`) resizes the character and sets `data.Character.Height` **in place**, without a respawn, so `PlayerService.Ready` never re-fires (it only fires on join/respawn — `PlayerService.luau:9`), and AgeService never requires `HealthService` to tell it to recompute. Result: this is exactly the M11 bug the task exists to fix (growing taller doesn't add health), just moved — it's fixed for the height read from the save at spawn, but still broken for the same aging system (M2-02, built alongside this) that changes height during a session. `.birthday` will not move `MaxHealth`/`Health` until the player next dies or rejoins.
   Fix: have the shared regen loop (`HealthService.luau:262-296`) also recompute `MaxHealth` from `data.Character.Height`/rank each tick using the same "top up only if already full" rule `setupCharacter` uses (it already fetches `data` there for the Rank/Epithet/Alignment refresh, so this is a few lines, not a new poll), or give `AgeService` a way to call back into `HealthService` after `resizeCharacter`.

2. **[Low, documented] Old `BlockHandler.client.luau` HUD bar goes stale between this merge and M2-04's.** `HealthService` doesn't write `IntFold.BlockInt`/`MaxBlockHpInt` (SYSTEMS.md's new §"Health and block" says so explicitly), and `BlockHealthRegen.server.luau` — the only thing that regenerated those Values — is removed here. Until M2-04 removes `StarterGui/HUD/BlockHandler.client.luau` too, the old block bar will render frozen in Studio. Already disclosed in SYSTEMS.md as a known gap, and the fix is already scoped to M2-04, so this is a merge-order note for the lead (merge M2-03 and M2-04 together, or accept a frozen bar for one playtest pass) rather than something to send back to the builder.

## Parity with the old scripts (numbers changed, as reported)

- Max health: old was race-branched (`50 + 100 + 10×Height` etc., using `MaxMagoi`); new is `Base(50) + HeightBonus(3)×Height + RankBonus[rankIndex]` since Race is fixed to Human and Magoi now drives rank (DESIGN 3a) instead of health. `RankBonus = {0,10,20,35,50,70,100}` is new (7 entries, one per rank) — matches the spec value exactly.
- Regen: old `Rate=1/250 × wait-interval` (L8 bug: tiers didn't matter) → new flat `RegenPerSecond = {Idle=2, Combat=0, Knocked=1}`. Matches spec.
- Block refill: old `Rate=1/750` (~12.5 min) → new flat `BlockRegenPerSecond=10`, `MaxBlock=100`. Matches spec.
- All changed numbers are listed in SYSTEMS.md and match `Config.Health`; self-test (`SelfTestService.luau:483-494`) checks `MaxHealthFor(1.0,1)=53`, `MaxHealthFor(1.3,4)=88.9`, and the three regen tiers over 5s — all correct by hand.

## Everything else checked, no issues found

The regen loop only raises health while `Health > 0`, so it can't fight a real death. `setupCharacter`'s "top up only if already full" rule keeps a mid-fight player's current health sensible across a MaxHealth change. `InteractionsDesign.server.luau:245-268`'s health-ratio walkspeed loop only *reads* Health, doesn't write it.
