## Findings
1. MEDIUM `init.luau:267-285` + `:361-372`: the distance watcher calls `closeBoard()` from inside `boardWatchThread`, and `closeBoard` does `task.cancel(boardWatchThread)` on the running thread. Cancelling yourself can abort the rest of `closeBoard` (connections left connected, board GUI not destroyed). Fix: in the watcher set `boardWatchThread = nil` before calling `closeBoard()` (or skip the cancel when `coroutine.running() == boardWatchThread`).
2. LOW `:406-411`: the X only fires `MissionExit`; the board stays open until the server answers `MissionBoard nil`. Same for Start (old code destroyed the GUI at once). If the server is slow or M5C-01 is absent the buttons appear dead. Fix: also `closeBoard()` locally on X (Start may stay server-driven).
3. LOW `:519-541`, `:593`: for a normal run the tracker/distance use the `<City>Delivery` part's position, and `destinationPosition` is ignored. Spec says distance to `destinationPosition`; with placeholder routes the two can differ. Fix: always anchor to `destinationPosition` when present (fall back to the part).
4. LOW `:557-559`: at 0:00 the countdown reads "Complete in 0:00" until the server sends Failed; the old code showed "Failed." and greyed the BONUS text (43,43,43). Fix: when remaining <= 0 set Constraint "Failed." and BONUS TextColor3 to 43,43,43 (the old Fragile-package fail state also had this; server has to send it).
5. LOW `:243-256`: `folder.ChildAdded` and per-player `CharacterAdded` connections are never stored (`Start` runs once, players' connections die with the Player, so no real leak). Optional: keep them in a table for consistency.
