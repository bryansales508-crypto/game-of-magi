## Findings

**H1 (high) Modifier names don't match the client.** `Cities.luau:173-190`, sent at `MissionService.luau:241,334`. The server sends the key (`"TimeCrunch"`, `"CourierLoop"`), but the client matches the display name (`TIME_CRUNCH_NAME = "Time Crunch"`, `COURIER_LOOP_NAME = "Courier Loop"`, client `init.luau:78-79`) and shows `name` as the pop-out title. Result: the TimeCrunch countdown and its grey fail state never run, the CourierLoop return text never shows, and the pop-outs lose Bryan's titles ("Very Important Noble", "Clear the Route"...). The old `MissionDeliniation.Modifiers[*].Name` lore was dropped.
Fix: add `displayName` to each `ModifierDef`, copied word for word from the old table. Send `{ key, name = displayName, chance, text }`, or agree the field with the client and make one side match.

**H2 (high) CourierLoop's "Cleared" state breaks the client.** `MissionService.luau:649-657`. Once the first leg is done the server sends `state = "Cleared"`. The client treats "Cleared" as the end of the run: it calls `teardownRun()` and shows "Delivery cleared." (client `:708`). It re-arms the tracker only on `"Started"` with `returnPosition` set (`:634`). So the return leg has no tracker and no quest box, and the player thinks the run is over.
Fix: send `sendUpdate(player, run, "Started")` once `returnPosition` is set. The client already handles that case.

**M1 (medium) One error stops every delivery.** `MissionService.luau:877-882`: `tick()` is not protected. One error (in `GiveCopperValue`, `AddDeed`, `SetAttribute` on a destroyed character, and so on) kills the only loop for the whole server. After that no arrival, timer, beacon or board close ever runs again.
Fix: `local ok, err = pcall(tick); if not ok then log:Warn(...) end` inside the while loop.

**M2 (medium) Two accounts can farm interception without travelling (Bryan to decide).** `MissionService.luau:585-590`. Account A opens the board and starts a run; account B knocks A out next to the board and gets the full reward at once. Repeating this pays a delivery's worth of Copper and a Black Rukh each cycle, with no travel. SYSTEMS 7 says "nothing to farm", which isn't accurate.
Suggested fix, needs Bryan's OK: interception pays only when the courier is at least N studs from `originPosition` or at least T seconds into the run. Otherwise the run fails with no payout.

**M3 (medium) Reopening the board re-rolls modifiers and pay.** `MissionService.luau:252-271, 517`. Each `MissionOpenBoard` (2 per second) rolls fresh modifiers and pay, so a player can keep reopening until they get VIP ×2 or HighlyValuable ×1.5. The old code kept a player's roll per city (`CityMods`, `MissionHandler:228`) until a run to that city was used.
Fix: cache the rolls per player per destination and clear that entry when a run to it starts.

**M4 (medium) Clear the Route pays its bonus without clearing anything.** `Cities.luau:183-189` with `ComputePay`. The ×1.5 is always in `pay`. In the old code the bonus counted only if the courier gripped someone (`MissionHandler:331-336, 451`), which is what the spec meant by "without the old error".
Fix: leave its multiplier out of `pay` and add it only when the run records a knockout or grip, or ask Bryan whether a flat bonus is fine.

**M5 (medium) Fragile Package survives light hits.** `MissionService.luau:581-584`. The run only fails on the `Hit` status, and CombatService applies that only for Heavy hits (`CombatService.luau:643`). A courier can take any number of landed light hits. The spec says "fails on a landed hit taken".
Fix: have CombatService expose a server `HitLanded(target, attacker)` signal and listen to it, or watch HealthService damage events.

**M6 (medium) The package lost its modifier look (keep-the-look rule).** `attachPackage`, `MissionService.luau:282-325`. The old FragilePackage turned the pack to glass (`Material.Glass`, `Color3.fromRGB(168,187,208)`, `MissionHandler:276-286`). The old HighlyValuable added the `trueSparkle`/`sparkle1`/`sparkle2` VFX and a gold Highlight on the pack that pulsed 1 s in, 6 s on, 1 s out, 20 s off (`:303-328`). Both are gone.
Fix: port both in `startRun` after `attachPackage`, with the sparkle pulse on the shared tick and nothing per frame.

**L1 (low) Leaving mid-run keeps the streak.** `MissionService.luau:852-861`. On leave, the `PlayerRemoving` handler only clears local state and may run before `CharacterRemoving`, so the streak isn't reset. A courier can log out to escape a failing timer or an ambush with the streak intact.
Fix: call `failRun` from `PlayerRemoving` before clearing state (DataService ends the session in its own handler; check the order).

**L2 (low) Attributes go stale after NewLife.** The save resets on a new life, but the `MissionStreak`/`Bounty` attributes aren't refreshed until the next join.
Fix: refresh them from a DataService new-life hook, or from `LegacyBridge.Refresh`.

**L3 (low) The interceptor is found by name.** `MissionService.luau:586-588` resolves `by` with `Players:FindFirstChild(by)`, so an NPC whose model name matches a player's username would pay that player.
Fix: pass `byUserId` (or the Player) in the Knocked data.

**L4 (low) The chance shown is the raw weight.** The client shows `chance` (the roll weight, for example 20) as "20%". The real odds depend on the eligible pool. This matches the data but isn't a true percentage; tell Bryan.
