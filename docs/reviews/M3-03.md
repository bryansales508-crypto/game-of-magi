## What holds up
- **C2 is fixed.** `Attack()` takes no args and `Block` takes a validated boolean (rate 6/s and 4/s). The client never names a target or sends a number. The hit check is server geometry (`GetPartBoundsInRadius`), it excludes the attacker, and it walks up to the Model that owns a Humanoid, so packs and weapons count (M3/P2). An attack across the map is impossible unless the attacker's own HRP is actually there (see L3).
- **Attack gating** checks dead, Stun, TrueStun, Knocked, Block and `NextAttackAt = now + windup + recovery`. A click flood is capped twice.
- **Events and attributes match the built client exactly.** Checked against `claude/combat-controller-85cacr`: `Swing{character,setName,moveIndex}`, `Hit{attacker,target,moveIndex,finisher,knockback}`, `Blocked{target,attacker}`, `Parried{attacker,target}`, `BlockBroken{target}`, `Knocked{target,by}`, `Recovered{target}`, plus `ComboStep`, `NextAttackAt` and `WeaponSet`. No mismatch.
- **Knockout** computes the new health before writing it, so `Died` never fires. Getting up restores `healthOnGetUp` and fires `Recovered`.
- **M1 is fixed:** a facing block takes no damage, stun, slow or knockback. A back hit ends the block and lands. **M2 is fixed:** nothing adds block HP any more.
- **Deletions** match TRIAGE #10 and #13. Keeping `Remotes/Hit` and `RagdollEvent` is justified because EffectsService still fires both. No live reader of the deleted files remains. MissionHandler only reads `Effects.Knocked` and `IntFold.GripInt`, and both are unaffected. MovementService now creates `IntFold` and `Running?`.
- Dev commands go through DevService, which checks `IsDev` on the server. `--!strict`, Log only, `task.*`.

## Findings (security first)

**H1 (high, CombatService.luau:237/263): a knocked-out target can be knocked out again forever.** A knocked target sits at 1 HP, so every hit takes the "lethal" branch and calls `Apply("Knocked")` again. That restarts the 8 s timer. Punching every 0.48 s keeps someone down indefinitely (griefing). The old DamageHandler skipped any target that was already `Knocked`.
Fix: `if StatusService.Has(target, "Knocked") then return end` in `ApplyHit`, and state this in SYSTEMS 9.

**H2 (high, CombatService.luau:340/411): an attacker can block during their own windup and still land the hit.** `Attack` only rejects Block when the swing starts. `runHitCheck` never checks Block, and `SetBlocking(true)` doesn't check for a pending swing. The loop is: click, press F within 0.22 s, the hit lands while the attacker is shielded with a fresh parry window, release, repeat. That stays inside the 4/s Block rate.
Fix: bail in `runHitCheck` if `StatusService.Has(attacker, "Block")`, or reject `Block(true)` while `now < lastSwingAt + move.hitTime`.

**M1 (medium, :198): a parry costs block HP.** `SpendBlock` runs before `ResolveBlock`, so a successful parry still drains 35.
Fix: resolve the parry first, and call `SpendBlock` only when the outcome isn't `Parried`.

**M2 (medium, :424/430 and HealthService.luau:308): block HP keeps refilling while you block.** `HealthService.SetBlocking` is never called, so the 10/s refill never pauses, and it takes about 4 hits to break the block instead of 3. `SetTier("Combat"/"Knocked")` is also never called, so regen stays at the Idle rate mid-fight and while knocked.
Fix: call `HealthService.SetBlocking(player, on)` everywhere Block starts or ends. Set the tier on hit and knockout, or note that for M3-04/M3-07.

**M3 (medium, :113 and SYSTEMS.md:248): Stun, TrueStun and Knocked don't remove Block,** although SYSTEMS 9 says they do. H2 plus a parry leaves the attacker with Stun and Block at the same time. The same happens via `.stun`/`.knock`, or when Block ends through StatusService (unregister, bridge ChildRemoved): the `Block` 0.6 speed modifier is left behind.
Fix: in `onStatusChanged`, when Stun/TrueStun/Knocked turns on, call `Remove(Block)`. When Block turns off by any path, clear the modifier (and HealthService blocking).

**M4 (medium, :456/532): `registered` leaks one entry per respawn.** Entries are only cleared on PlayerRemoving, and only if `player.Character` is non-nil. Every dead character's Model and entry stays in the table.
Fix: unregister on `Humanoid.Died` or on `AncestryChanged` to a nil parent, the way StatusService does.

**M5 (medium, :327): the hit check takes any Humanoid, in arbitrary order.** It isn't limited to *registered* combatants, so shopkeepers and cutscene rigs can be hit and knocked out, and StatusService auto-registers them. Also, `GetPartBoundsInRadius` does not guarantee nearest-first order, so "first target" is arbitrary in a crowd. The comment and SYSTEMS 9 claim otherwise.
Fix: skip `registered[target] == nil` and pick the one closest to the attacker's HRP.

**M6 (medium, FootstepService.luau:140/165): the port wasn't verbatim, and footprints now appear only on jumps.** The old `surfaceCall` raycast from Torso on *every* step. Now `floorResult` is nil for grounded steps, so no footprints appear on sand or mud while walking. That changes Bryan's look.
Fix: always raycast from Torso for the footprint, as the old code did.

**L1 (low, :307): no wall check.** A hit can pass through a thin wall within about 6 studs, and this isn't documented. Add an HRP-to-HRP raycast that excludes characters, or document it as accepted.
**L2 (low, :312): the sphere reaches about 1.6 studs behind the attacker's centre**, so someone pressed against your back gets hit. Add `(targetPos - attackerPos):Dot(look) > 0`.
**L3 (low, :346): the attacker's HRP is client-owned.** A teleport right at `hitTime` reaches anyone. Store the position at Swing and reject a hit if the attacker moved more than run speed × hitTime plus dash distance, or document this for M3-07.
**L4 (low, :382): `comboStep` keeps counting up (4, 5, 6…) after the finisher.** `ComboStep` and `moveIndex` go out of range, and the wrapped Jab plays. Wrap the step, or reset to 1 after a finisher. Also, the window is measured from the start of the swing, not "after it lands" as `Combat.luau` says. Align one with the other.
**L5 (low, :340): `runHitCheck` doesn't check that the attacker is still alive** (a dead attacker's swing can land).
**L6 (low, docs): stale knockout text.** HealthService `reviveLoop` still runs a second knockout timer on the bridged marker, and SYSTEMS 9 (l.269) and 10 (l.309/319) still say "DamageHandler / until M3-03". Section 12 says Animate fires Footstep, then blames PhysicalHandler. Remove `reviveLoop` or document it, and fix the text.
**L7 (low, EffectsService): duplicate effects after M3-06 merges.** EffectsService's server hit/block-break sounds, particles and Blind GUI will double the M3-06 client effects, and its block branch in `hitFunc` is now dead. The lead should schedule this trim with the M3-06 merge.
**L8 (low, SelfTestService): self-test gaps.** It has no parry window → flip → cooldown sequence and no drain-to-break sequence (only the pure `ResolveBlock`). Note for M3-04: an NPC's block never breaks (`meterHeld = true`).
