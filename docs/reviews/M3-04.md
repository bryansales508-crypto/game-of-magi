## Findings

**H1 (high, NpcService/init.luau:130-133; CombatService.luau:274-281): NPCs are never registered with HealthService, so their damage still runs the old pre-M3-04 side path.** The spec (`M3-04.txt` item 2, `M3-PLAN.md` M3-04 row: "same StatusService, MovementService, CombatService **and HealthService** paths") explicitly asked for `HealthService.Register(character, nil)` to be added if missing. It wasn't: `HealthService.luau` is untouched, still entirely `Player`-keyed, with no `Register` function at all. `NpcService.setupNpc` sets `humanoid.MaxHealth`/`Health` directly instead, and `CombatService.ApplyHit` still hits the `else` branch at :274-281 — whose own comment says *"Pre-M3-04: no NPC is ever a real combat target yet (NpcService registers them with HealthService itself once it exists)"* — mutating `Humanoid.Health` directly rather than through `HealthService.TakeDamage`. `docs/SYSTEMS.md`'s own new section 15 quietly lists `NpcService`'s dependencies as only `StatusService`/`MovementService`/`CombatService`, confirming the gap was known, not just missed.
Fix: add a Model-keyed `HealthService.Register(character: Model, npcType: string?)` (max health from `Config.Npc`, not rank), call it from `setupNpc`, and change `CombatService.ApplyHit`'s non-player branch to route through it so NPC damage takes the identical path a player's does.

**L1 (low, CombatService.luau:198): REVIEW-M3-03's L8 stands unfixed** — `meterHeld` is still hardcoded `true` for any non-`Player` target, so an NPC's block can never break. Doesn't currently manifest (neither Dummy nor Target ever blocks), but it's now doubly true once H1 is fixed and NPCs get a real block meter. Worth tracking with H1's fix rather than separately.

**L2 (low, NpcService/Trees.luau:40-55, docs/SYSTEMS.md:15): walk/run/flinch animation IDs aren't literally "the old ones."** The old `NPController.luau` never contained animation IDs (they lived only in the deleted Studio-only `NPCFetch`/`Health` scripts), so the by-name `Animation` lookup fallback is the best available substitute — already honestly flagged with a ⚠ in SYSTEMS.md for Bryan/the playtester to fill in. Not blocking.
