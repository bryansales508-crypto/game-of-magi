## New findings from this round

| ID | Sev | Where | What's wrong → fix |
|---|---|---|---|
| N1 | high | `init.luau:574-575` vs `Interactions/CollisionsHandler.server.luau:18-20` | F6's fix makes `CharacterService:Init()` register `ClothingRackGroup` itself when missing, and `Init()` runs at server boot (`Main.server.luau`'s `Init()` pass), always before `CollisionsHandler.server.luau`'s `repeat task.wait() until game.Loaded` resolves. That script then calls `ps:RegisterCollisionGroup(clothingRackGroup)` **unconditionally, with no guard or pcall** — the exact pattern this codebase elsewhere pcall-wraps because a duplicate `RegisterCollisionGroup` name throws (see the old, pre-fix `CharacterService:Init` in `a00efc6`, and the M8 audit note). If it throws here, `CollisionsHandler.server.luau` aborts before its `for _,v in game.Workspace:GetDescendants()` loop (`:22-27`) ever assigns `ClothingRack` parts to the group — so the parts never actually get `CollisionGroup = "ClothingRackGroup"`, and players collide with clothing racks again, the exact symptom F6/M8 targeted. `CollisionsHandler.server.luau` is outside `CharacterService`'s owned files, so this needs either a guard added there (`if not ps:IsCollisionGroupRegistered(clothingRackGroup) then ... end`) or `CharacterService` should stop pre-registering `ClothingRackGroup` and only guard `SetCollidable` itself with an `IsCollisionGroupRegistered` check (skip-and-retry-next-spawn, closer to the original F6 ask). Playtester should confirm in Output whether this actually throws. |
| N2 | low | `init.luau:583-593` vs `:497-521` | New transient-stale-attribute window: the `CreateCharacter` remote handler calls `setAttributes` (`:591`) right after `ApplyCreateCharacter`, while `Character.Height` is still the unrolled `10` sentinel (the F2 roll hasn't run yet — it happens later on `buildCharacter`'s own thread). `HeightStuds` briefly reads the wrong (default) value between that call and `buildCharacter`'s second `setAttributes` (`:530`). Harmless today (nothing reads `HeightStuds` before the character finishes building), but worth a one-line note if a future client feature reads it during creation. |
