## Findings

**C1 (critical): new players and `.wipe` get combat unlocked, so the "earned" flag can never be false.** `SaveSchema.luau:80` template `Version = 1`, and `Migrate` runs `Migrations[3]` (`SaveSchema.luau:154`) on every save below v3. A brand-new profile (template copy, then Reconcile, then Migrate in `DataService.luau:151-152`) and `DataService.ResetToTemplate` (`DataService.luau:283`, used by Wipe) both walk v1 to v3, so `Meta.Unlocks.Combat = true`. The self-test "Wipe's reset ... clears Meta.Unlocks.Combat back to the template's false" (`SelfTestService.luau` testDataService) will FAIL in Studio. It only passes check.sh because static checks don't run it. This is hidden today by `UnlockedByDefault = true`, but it breaks the tutorial gate the moment Bryan flips it. Fix: set template `Version = Config.Data.SchemaVersion` (a fresh template is already current), or gate the migration with `if data.Meta.Created ~= 0 then`. Add a self-test that migrates a raw `deepCopy(Template)` and expects `false`. Also correct the SYSTEMS §1 migration note.

**H1 (high): knockout and death don't clear the stance.** The spec says "knockout, death and the death scene clear it". Only the death scene does (`AgeService/init.luau:221-227`). In `CombatService.luau:338` (`onStatusChanged` Knocked branch) nothing sets `InCombat=false`, so a player knocked while in the stance gets up still InCombat and can attack instantly. `humanoid.Died` (`CombatService.luau:1272`) only calls Unregister, so the corpse keeps `InCombat=true` and other clients keep playing the stance idle on it. Fix: in the Knocked `active` branch, and in the Died handler before Unregister, set `InCombat=false` **only when `entry.owner ~= nil`** (NPCs stay InCombat). Add a self-test: enter the stance, apply Knocked, expect InCombat false.

**M1 (medium): a bogus `Weapon` name is silently ignored.** The lead's spec says it should fall back to Fist with a warn. `onToolEquipped` (`CombatService.luau:1206-1211`) just returns. Say a Dagger was equipped and then a Tool with `Weapon="Sword"` gets parented in: the style stays Dagger with no log. Fix: on a string that isn't a known style, `log:Warn(...)` and `SetWeapon(character, "Fist")`.

**L1 (low):** `SetUnlocked(player, false)` (`CombatService.luau:1356`) and `.lock combat` leave a player already InCombat in the stance. Fix: also `SetStance(player.Character, false)` when locking.

**L2 (low):** SYSTEMS §16 (Dev commands, L423-470) doesn't list `.unlock combat` / `.lock combat`. They are listed only in §9 L286. Add them to §16.

**L3 (low, no fix needed):** SetStance spam at 4/s can strobe the stance idle for others. This is cosmetic only and within the rate limit, so it's acceptable.
