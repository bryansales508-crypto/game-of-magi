## Findings
1. **HIGH** `DataService.luau:79-88`: the Mock fallback isn't limited to Studio. If `StartSessionAsync` throws once in a **live** server, `useMock` flips to true for good. Every later player in that server then plays a blank Mock save that is never written, and nothing warns them. It only throws on programmer errors, such as "already loaded in this session" when `onPlayerAdded` runs twice for the same player (see #6). ProfileStore already switches to Mock by itself in Studio when the API is off (`DataStoreState ~= "Access"`, 394/604/2080-2110). **Fix:** fall back only `if Config.IsStudio`; in live, log an Error and kick.
2. **MEDIUM** `DataService.luau:39`: `useMock = Config.Debug.FreshSave` doesn't check for Studio. If FreshSave=true ever gets published, no live save persists. **Fix:** `Config.Debug.FreshSave and Config.IsStudio`.
3. **MEDIUM** `SaveSchema.luau:112-120`: the comment contradicts the code. It says migrations are keyed by the version they upgrade FROM ("Migrations[1] turns a v1 save into a v2 save"), but `Migrate` (129-130) runs `Migrations[version]` for the TARGET version. A v2 migration written the way the comment says would be skipped silently while Version still bumps to 2. **Fix:** key by target version and change the example to `Migrations[2] = function(data) ... end`.
4. **MEDIUM** `LegacyBridge.luau` (Build): `OnCharacter.Position` (a Vector3Value) is missing. The old `OnCharacterStore2.server.luau:153-155` always created it; only the saving was commented out. `SSS/Character/LocationHandler.server.luau:20` does `WaitForChild("Position")`, which waits forever, so the spawn teleport stops working until M1-04S deletes that script. SYSTEMS.md §1 says the opposite. **Fix:** create an unsaved, one-way `Position` Vector3Value (0,0,0) in `OnCharacter` and correct the doc line.
5. **MEDIUM** Legacy behavior lost: the old OnCharacterStore2 was the only code that updated the coin purse HUD text (`PlayerGui.Currency.Bank.CoinPurse.<Copper|Silver|Gold>.Text`, on load and on change, old 60-62/75-82/185-188) and played the `CoinReward` sound on Torso. Nothing does either now: grep finds no other `CoinPurse` writer, and the client copy in `RegionHandlerPart1.client.luau:141-155` is commented out. The acceptance line is "old systems still work through the bridge". **Fix:** in the bridge's currency watchers, set the purse text on Build and on change, and play the sound on change. Alternatively, Bryan explicitly accepts this as a known gap until the Economy milestone.
6. **LOW** `DataService.luau:242-251`: nothing stops `onPlayerAdded` from running twice for the same player (PlayerAdded plus the Start loop). Combined with #1, this is the path that causes it. **Fix:** keep a `loading[player]` set and return early if the player is already loading or loaded.
7. **LOW** `LegacyBridge.luau:74-109`: under Deferred SignalBehavior, the default now, `.Changed` handlers run after `mirroring` is reset, so the echo guard does nothing. The only cost is that echoes rewrite identical values back into data. **Fix:** none required; correct the comment, or compare against data before writing.
8. **LOW** `DataService.luau:176-184`: `WaitFor` checks every frame. **Fix:** wait on `Loaded` or a per-player BindableEvent instead (optional).
9. **INFO** New players now start with the template's fixed look (FirstName "", EyeColor 1, black hair, MaxMagoi 0) instead of the old random rolls and MaxMagoi 10. `Health.server.luau` therefore gives Humans 5 less max HP. This follows the spec; Bryan should know about it.
10. **INFO** `scripts/check.sh` counts lint warnings from vendored `Packages/` as "errors". Consider excluding `Server/Packages` from the luau-lsp targets.
