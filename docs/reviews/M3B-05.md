## Findings

**M1 (medium): the respawn with lives left happens instantly, and the global 35s RespawnTime creates side effects.** `LifeService.luau:85` calls `player:LoadCharacter()` synchronously inside `Humanoid.Died`, so the player pops back the same frame with no death moment. The spec said to let Roblox/PlayerService respawn. `LifeService.luau:143` also sets `Players.RespawnTime = 35` for everyone. The effect: any death that `onDied` skips (`data == nil` at L70, e.g. a profile that isn't loaded yet or has been released) waits 35s to respawn. `CharacterAutoLoads` is still true, so the playtester must confirm that the engine doesn't respawn the player a second time 35s after a `.kill` with lives left. Fix: add `Config.Life.RespawnDelay` (about 3s) and replace L85 with `task.delay(delay, function() if player.Parent == Players and player.Character == deadCharacter then player:LoadCharacter() end end)`, passing `character` into `onDied`. In the `data == nil` branch, respawn the same way.

**M2 (medium): the self-test is missing two cases the spec lists.** `SelfTestService.luau` `testLifeService` covers 3->2 and 1->0 (pure `HandleDeath`), and the template. NewLife->4 and Unlocks survival are covered in testDataService. Missing: (a) **a knockout never changes LivesLeft**, e.g. a lethal `CombatService` hit on a scratch registered rig leaves `Health == 1` with `Knocked` applied, so `Died` never fires; (b) **a fatal heart attack with 4 lives left still wipes**, e.g. assert that the heart-attack path never reads `LivesLeft`, or run `ResetToTemplate` on data with `LivesLeft = 4` and `Meta.Lives = n` and expect a new life with `Lives = n+1`. Add both.

**L1 (low):** `Died` has no idempotency guard for each character. `LifeService.luau:99` uses `:Connect`. Fix: `humanoid.Died:Once(...)`, which also keeps a stray second fire from charging two lives.

**L2 (low):** `.lives` accepts negatives and huge numbers (`LifeService.luau:117`). Fix: `math.clamp(math.floor(n), 0, 99)`.

**L3 (low):** `SaveSchema.luau` Migrations[3] comment ("so retuning LivesPerCharacter later doesn't leave an old save's migration frozen") is misleading. Fix: say it is redundant with Reconcile's backfill and exists only to be explicit. SYSTEMS §4 L134 and §9 say "a dev `.wipe`", but the command is `.fresh` (`DevService.luau:614`). Fix: correct the name.

- **The rule:** `HandleDeath` decrements; >0 respawns the same character without the scene; 0 goes to `AgeService.StartDeathSequence(player, data, "lastLife")`, which fires `Died {cause="lastLife"}`, freezes, NewLife, waits for `RukhSceneDone`/timeout, then LoadCharacter. The heart attack calls the same function with `"heartAttack"` and ignores LivesLeft. The client handler checks `data.cause == "lastLife"` and fires `RukhSceneDone`.
- **Idempotent:** `Dying` is set on the first line of StartDeathSequence, and `task.spawn` runs it synchronously, so a second death during the scene (last-life or heart attack) is ignored by the guard at `LifeService.luau:61`. A knockout sets Health to 1 before 0 (`CombatService.luau:611`), so it never fires `Died`.
