## Findings

**L1 — `EffectsController/init.luau:405-408`.** `updateBleedVisual`'s `character.Destroying` cleanup hook is wired inside `if not visuals then ... end`, so a character that bleeds, clears (stacks hit 0, `clearBleedVisual` nils the entry), then bleeds again gets a second `Destroying:Connect` — one more per cycle, never disconnected. Each extra connection is harmless on its own (`clearBleedVisual` is idempotent) and all of them drop when the character is actually destroyed, so this isn't a real leak, just wasted connections. Fix: track "already wired" separately from `bleedVisualsByCharacter` (e.g. a small `destroyingWiredFor` weak set) so the hook is connected once per character, not once per bleed cycle.
