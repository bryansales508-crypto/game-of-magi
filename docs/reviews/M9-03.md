## Findings
1. **Low** `C:368-450` Carried-input freeze is independent of EffectsController. If the carried player is not `Knocked`, we `Disable()` controls; if `Knocked` then arrives, `updateCarriedUi` calls `unfreezeInput()` → `Controls:Enable()` while the knockout freeze should hold. In practice carry requires `Knocked` and the server keeps it refreshed, so it is a rare edge. Note: fix by only unfreezing if we froze and not Knocked, or by sharing one freeze counter.
2. **Low** `C:462` `jailActive()` is true on the `Jailed` attribute alone; with `JailUntil` = 0 (e.g. a dev jail) the panel shows "0:00". Cosmetic.
3. **Low** `C:243-249` `resolvePath` splits on "." so an instance name containing a dot would not resolve (logged once, no glow). Bryan's current Jail names are fine.
4. **Low** `C:104`/`C:294`/`C:315` Prompts use `Exclusivity = OnePerButton`, so an unrelated E prompt could still show beside them. Intended; just worth a look in playtest.
