## What passed

- **BUG-49 ShopController:** every rack is registered and measured on its own (the single-anchor gate is gone). Each rack gets its own prompt and highlight again. Only one prompt is on at a time. Hovered rack wins; with nothing hovered and exactly one rack in reach (gamepad/touch) that rack's prompt shows; several in reach with no hover shows none. A prompt the server re-adds starts off and is decided next frame. `Destroying`, `ChildAdded` and ClickDetector connections are tracked and torn down; no character means everything is hidden. No remote or args changed, and nothing in init can throw. (The cost issue is finding 1.)
- **BUG-52 DevController:** `appendReply` is the one path for server replies (`DevReply`) and forwarded local commands (`DevLocalCommand`), and it writes to the panel and to the RBXGeneral chat as a system message. `.music play` resumes, `.music volume` works, and unknown local commands reply "unknown command: ..." through the same path.
- **FEAT-62 MusicController:** `Current/Play/Stop/SetVolume/Volume/IsPlaying/OnChanged` are the single source of truth for both the panel and `.music`. The panel is `ResetOnSpawn=false`, uses Bryan's brown/orange/tan palette and Merriweather Bold, and the slider handles mouse and touch drag with a wide hit area. Volume applies live to the current track, cancels an in-progress fade-in so it isn't overwritten, and is used for later tracks. It is remembered for the session in the `MusicVolume` player attribute. The track name and Play/Stop label update on every change. `Stop` leaves ambient layers alone. Nothing runs per frame when idle (only input events while dragging).
- **BUG-53/54 MissionController:** city buttons are slot > coloured Frame (0.9 x 1, centred) > TextButton (0.9 x 0.7, Merriweather Bold 18, black border, Rathole's border = fill), matching the dump, with colours from the server. The modifier card shows name, description and chance percentage only. The `!!!` label is destroyed with its template, and the M7-04 clamp/AutomaticSize is untouched. **BUG-55 client half:** there is no HV beacon suppression anywhere in MissionController, so nothing to remove.
- **BUG-57:** `StarterPlayerScripts/RbxCharacterSounds.client.luau` is the correct name and location to override the engine script, and it is documented. It keeps Died, Climbing, GettingUp, Jumping, Landing, Splash, Swimming and FreeFalling and never creates Running. Run steps come from the run track (matched on `Config.Combat.MoveAnimations.Run`) every half loop, or every `RunStepSeconds` if set, alternating Left/Right. Animate's Left/Right and the distance fallback are ignored while `runDriving`. Jump events still fire. Run to walk resets `runDriving`/`runTrackedLast`, so the walk path takes over after the usual grace (no double step, no permanent silence). Airborne and respawn (`clearStepConnections`) reset it. `Debug = false` by default. The walk path is unchanged.
- **BUG-61 EffectsController:** `Config.World.Sfx.Dash = "QuickDash"` matches `SFX.CombatSounds.QuickDash` in `m6-studio-dump.md:238` and the old PhysicalHandler. It is played once per `CombatEvent Dash` for any character, cloned onto the dasher's root part and cleaned up with `Ended` plus Debris. A missing sound logs one warning. The server only pre-clones the sound into Torso and never plays it, so there is no double.
- **General:** `--!strict` everywhere except the engine override, `Shared/Log` only, connections tracked, only `Config.World` touched in Config (frozen), Bryan's look preserved.
