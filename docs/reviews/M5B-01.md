## Findings

1. **Medium** - `ShopService.luau:142-161` (`clearStock`). Undressing a rack on `.shop restock` resets `Transparency` and clears `ShirtTemplate`/`PantsTemplate`, but never restores `CollisionGroup` back to `"ClothingRackGroup"` (the no-collide group `Interactions/CollisionsHandler.server.luau` assigns every `ClothingRack` part at boot). `dressRack` (line 327) sets it to `"Default"` when stocking. After any restock, a rack that was dressed last time but isn't redressed this time is left invisible (`Transparency = 1`) yet still solid in `"Default"` - players can collide with an invisible box. Fix: in the `clearStock` rack loop, set `part.CollisionGroup = "ClothingRackGroup"` alongside the transparency reset. Doesn't affect the very first (boot) stocking, since `dressedRacks` is empty then.

Double-trigger note (not a finding): there's no explicit per-player+prompt debounce, but it's safe today because `Wear` writes the `Gear` ownership field *before* its only yield (`ItemService.Equip`'s accessory wait) - a second `Triggered` for the same code during that yield sees `Owns() == true` and is rejected. This is implicit, not structural; a future change that adds a yield before the `Gear` write would break it silently.
