## 2. Bryan's refinements

(a) Modifier failure never ends a run: **confirmed.**
- TimeCrunch expiry, `onHitLanded` (Fragile/VIP) and Clear the Route at finish all go through `failModifier`. It is idempotent via `MarkFailed`, so `ModifierFailed {key}` goes out once per key.
- `failRun` is reached only from leave, respawn/CharacterRemoving, the tick's character check, a too-early knock, an NPC/self knock, and `.mission fail`. Interception goes to `interceptRun`.
(b) HighlyValuable beacon: **confirmed.** `beaconPermanent` sets `CourierBeacon` true at start and the shared cycle is skipped for it. It is cleared in `cleanupRun`.
CurrentPay: `floor(base * combined-of-intact)`; base >= 1 and every multiplier >= 1, so it can't be negative and is whole Copper. Interception computes `payout = currentPay(run)` once and uses it for the Copper and for Bounty; `TrySettle` prevents a second payout. **But see F2 (the combine rule is additive, not a product).**

## Findings

**F1 (medium) L1 is not actually fixed: leaving mid-run still keeps the streak.** `MissionService.luau:1240-1258` (comment at `:1236-1241` is wrong). `Profile:EndSession()` spawns the save, and the save fires `OnSessionEnd` synchronously before its first yield (`ProfileStore.luau:725-739`). DataService's handler nils `profiles[player]` (`DataService.luau:169-170`). DataService's `PlayerRemoving` is connected in Init, before MissionService's in Start, so by the time `failRun` runs, `DataService.Get` returns nil and `ApplyFailure` is skipped. The streak is saved unreset.
Fix: fail the run before the session ends (a DataService `Releasing`/pre-EndSession signal, or connect MissionService's leave handler earlier), or reset the streak in the same handler that owns the release.

**F2 (medium, confirm with Bryan) Pay combines additively, not as a product.** `Cities.luau:324-330`: `1 + sum(mult - 1)`. Two modifiers of 1.2 and 1.3 give x1.5, not x1.56. This is the old `citymodifier + 1` port and the self-test pins it (1.5). Your brief says "product of intact multipliers". If the product is intended, change `CombinedMultiplier` and the tests. If additive is intended, fix the wording. The numbers are consistent everywhere else (preview, live pay, interception).

**F3 (medium) Failed modifiers un-grey on the CourierLoop return leg.** `MissionService.luau:sendUpdate` sends every rolled modifier but no failed set. The client `startRun` tears down and rebuilds all pop-outs on the return-leg `"Started"`, so a TimeCrunch/Fragile/VIP modifier that already failed shows as active again (pay is still right). Fix: add `failed = { key, ... }` to the Started payload, and have the client re-apply it, without re-firing ModifierFailed (which must stay once per key).

**F4 (low, Bryan's call) The killing blow costs the interceptor Fragile/VIP pay.** `CombatService` fires `HitLanded` before the knockout, so `onHitLanded` marks Fragile/VIP failed just before `interceptRun` reads `currentPay`. Result: a VIP courier's x2 is always lost to their interceptor, and Fragile's x1.3 too. Conversely, Clear the Route's x1.5 is paid to the interceptor although the courier never earned it. It is consistent with "the same current amount", but probably not the intent.
Fix if unwanted: in `interceptRun`, use the pay as it stood before the knocking hit (snapshot in `onHitLanded`), or accept and document.

**F5 (low) No test for the wire helper.** `wireModifiers` (`:340-346`) is the H1 fix itself but is a local, so nothing pins `{key, name, chance, text}`. Consider exporting it (or a pure builder) and adding a self-test.

**F6 (low) M2 gate is easy to satisfy by waiting.** `CanIntercept` accepts 30 s standing still at the board. Two accounts can farm at a rate of one reward per ~30 s. Tunable in Config; tell Bryan.
