## Security (H6)
Client sends only `Attack()`, `Block(bool)`, `Dash(x, z)`, `Run(bool)` —
never a hit target or damage. No client-side authority: the swing plays
only on the server's `CombatEvent Swing`, the block pose only on the
`Blocking` attribute, the dash animation only on `CombatEvent Dash`, the
run zoom/leg animation only on the `Running` attribute. The pre-fire
attribute checks (`Stunned`/`Knocked`/`TrueStunned`/`Blocking`,
`NextAttackAt`/`NextDashAt`) only gate whether the client bothers to
fire — they never assume the server accepted.

## H6/L11 and robustness
Single `ContextActionService:BindAction` in `Start()` (one bind, not
per-character); `Remotes.Client.On("CombatEvent", ...)` bound once;
per-character connections (attribute/MoveDirection/StateChanged) live in
one table, disconnected in `teardownCharacter` on every `CharacterAdded`
and `CharacterRemoving`, with a stale-respawn guard in the async track
loader. No globals, no `wait()`, `task.spawn` only, `--!strict`, `Log`
only. Nil attributes at join and `Remotes.Client.Fire`/`On` on
not-yet-declared remotes (Attack/Block/Dash/Run/CombatEvent aren't in
`Remotes.Definitions` until M3-02/03) both fail soft (a logged error, no
throw), matching the spec.
