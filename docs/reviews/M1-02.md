## New findings
**N1 (medium, hang): `Client.Invoke` hangs forever if `InvokeServer` errors before it yields** (`Remotes.luau:354-371`). An example is an argument that can't be sent, such as a function. The worker then finishes synchronously inside `task.spawn`, while the caller is still running and hasn't yielded. It cancels the timeout and calls `task.spawn(caller, ...)` on a coroutine that isn't suspended, which errors. The caller then reaches `coroutine.yield()` (`:371`), and nothing ever resumes it.
Fix: start the worker with `task.defer(function() ... end)` instead of `task.spawn` (`:354`), so the caller always yields first.

**N2 (low, docs): the Invoke comment is wrong** (`Remotes.luau:336-339`). A server-side handler error arrives as `(true, nil)`, not `(false, reason)`, because the server returns nil (`:194`).
Fix: correct the comment. (Don't send the error text to the client; that was H1.)

Fix: check the name and kind like the server does, and `log:Error` then return (or return `false, "unknown remote"` from Invoke).
