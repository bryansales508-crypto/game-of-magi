## Findings
**H1 (high, security): Function handler errors reach the client.** `Remotes.luau:126`: `return handler(player, ...)` isn't wrapped. If a handler throws, the error text is sent back to the client's `InvokeServer` and the client can read it. The event path (`:109`) also runs handlers unprotected.
Fix: `local ok, ... = pcall(handler, player, ...)`; on failure, `log:Error` on the server and return nil to the client.

**H2 (high, security/perf): Rate limit only counts valid calls.** `CheckCall` (`:84-96`) validates arguments before `checkRate`, so bad calls never count. A client can send unlimited malformed calls, and each one triggers a `log:Warn` (`:103`, `:118`). That lets anyone flood the server's Output and CPU.
Fix: run `checkRate` first. Also throttle the "dropped" warning per player and remote (for example, once per window).

**M1 (medium, security/bug): Argument count uses `#{...}`.** `validateArgs` (`:49`) uses `#args`, and the length of a table with holes isn't well defined. `Fire("x", nil, junk)` can report a length of 1 and pass, and the handler still gets `junk` because dispatch forwards the original `...` (`:109`, `:126`). A trailing `Validate.optional` argument can never be left out either (`#{} = 0 ≠ 1`).
Fix: use `table.pack(...)` with `.n` (or `select("#", ...)`), allow `n <= #def.args` when the missing arguments are optional, and pass only the validated `args[1..#def.args]` to the handler.

**M2 (medium, strict): The 6 luau-lsp errors in Remotes.luau** (132-148) come from assigning new instances into `Folder?` and `RemoteEvent | RemoteFunction` locals.
Fix: build each instance in its own typed local (`local ev = Instance.new("RemoteEvent")`, set Name and Parent, then `instance = ev`), and do the same for `folder`.

**M3 (medium, leak): `Client.Invoke` leaks threads and hides failures** (`:222-245`). On timeout, the spawned thread stays blocked in `InvokeServer` forever, and an error or a timeout both return a plain nil that looks like a real result. It also polls every 0.03 s.
Fix: resume the caller with `coroutine.running()`/`task.spawn` plus a `task.delay` timeout (no polling), and return `(ok: boolean, ...)` so callers can tell a failure from nil.

**L1 (low, leak): A late call can re-create per-player state after the player leaves.** An event already queued after `PlayerRemoving` re-creates `rateState[player]` (`:61-65`), which then never clears. SelfTest's `fakePlayer` entry also stays forever.
Fix: skip the call if `player.Parent == nil`, and clear the fake player's entry after the self-test.

**L2 (low, bug): `Server.Init` isn't idempotent and trusts existing instances** (`:129-162`). Calling it twice doubles every connection. A leftover child with the right name but the wrong class gets force-cast and then errors.
Fix: guard with an `initialized` flag and check `existing:IsA(expected class)`.

**L3 (low): `Server.On`/`Handle`/`Fire` don't check the remote name or kind.** A typo silently registers a handler that never fires, and `Fire` on a Function remote errors on the cast.
Fix: assert that `Definitions[name]` exists and its `kind` matches, then `log:Error` if not.

**L4 (low): `table.freeze(Config)` is shallow**, so `Config.Debug.*` and `Config.Data.*` can still be changed at runtime.
Fix: freeze the sub-tables too.

**L5 (low, tooling): check.sh doesn't stop on a bad download.** An empty tag produces URLs like `download//…`. It also depends on the rate-limited GitHub API and always takes the latest luau-lsp and selene.
Fix: pin the versions, fail fast when a tag is empty, and drop the duplicate sourcemap analysis output.

## For Bryan
The new shared foundation (settings, logging, and the remote checker every future system will use) is well organized, and it correctly blocks bad numbers and wrong types.
Two gaps need fixing before anything is built on it. A crash inside a server handler can leak error details to a player. A cheater can also spam bad requests without ever hitting the rate limit and flood the server log.
The rest are small robustness and type-checking fixes. None of them change how the game looks or plays.
