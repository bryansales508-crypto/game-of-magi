## Fatal path, walked end to end
Birthday ≥60 → `DeathChance` roll fatal → `Dying=true`, humanoid frozen → `DataService.NewLife` immediately (`Meta.Lives+1`, `Meta.Created` kept, same table identity, bridge refreshed) → `HeartAttack(age, true)` already fired before the task spawned → wait on `RukhSceneDone`/30s timeout (unscaled) → `Dying=false`, `active[player]=true` → `LoadCharacter`. The new character is not frozen (`Dying` is already false by the time `PlayerService.Ready` checks it), the aging loop picks the player up again, growth re-rolls in `CharacterService.buildCharacter` once gender is chosen (post-`NewLife`, `Gender` is back to 0), and `ApplyHairColor` runs on that build.

- **NewLife twice for one death?** No — `Dying` is set synchronously inside `startDeathSequence` before `task.spawn` returns control, so no window exists for a second trigger to slip through the `Dying` guards.
- **Leaves during the scene?** Keeps the new life — `NewLife` mutates `profile.Data` in place before the wait; `PlayerRemoving` → `profile:EndSession()` saves that already-fresh state.
- **`.heart fatal` during a scene?** Correctly does nothing (`ForceHeartAttack` returns `false` on the `Dying` check before firing the remote) — see new finding N1 below for the message this produces.
