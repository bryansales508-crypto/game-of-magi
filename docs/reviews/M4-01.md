## What holds up
- Security: `ChooseEpithet` is rate-limited (3/10s) and range-checked
  (`Remotes.luau`); `ApplyChooseEpithet` (`RankService.luau:86-102`)
  re-checks range, requires `PendingEpithet`, uses only the stored
  `choices[index]`, never client text; a second call is rejected.
  `AddMagoi`/`AddDeed` have no remote at all.
- Schema: `SchemaVersion = 2`, `Migrations[2]` is a documented no-op,
  `Migrate` bumps `Version`, self-test covers v1->v2. `PendingEpithet`
  lives in `Progress` (persists), defaults to nil; `Wipe`/`NewLife`
  deep-copy the whole template first, so a fresh life can't inherit a
  stale pending choice.
- Flow: rank-up/alignment detection is event-driven off `AddMagoi`/
  `AddDeed` (`.magoi`/`.magoi+`/`.rukh`/`.rankup` re-routed through them,
  :337-403); `pick3` uses the current alignment/gender, current epithet
  excluded (:128-163); `RankUp` fields match the contract; resent
  unmodified on `Loaded` when pending (:269-300); origin fires once on
  `Gender` non-zero with `Epithet == ""` and no pending, never for a
  returning player with an epithet (`ShouldOfferOrigin`, self-tested);
  `AlignmentChanged` only fires off `White` (which only occurs below
  `Alignment.MinDeeds`, so the deeds rule holds by construction);
  rank-down is silent (:194-196); all five attributes are written only by
  `RankService` now.
- Leaks/races: no shared loop; one `Gender` connection per session,

  `AddMagoi`/`AddDeed` nor `NewLife`/`Wipe` yield, so a rank-up can't

- `--!strict`, `Log` only, no `wait()`/`print`; dev commands are gated on

## Findings

**H1 (RankService.luau:128, 194-196): a rank-up while a choice is already
pending silently overwrites it, and can permanently skip the origin
choice.** `announceRankUp` unconditionally overwrites `PendingEpithet`;
`AddMagoi` calls it on any `newIndex > oldIndex` with no check for an
existing pending choice. If `Magoi` crosses a threshold before a still-
pending card is answered - including the origin card (`Epithet` still
`""`) - the new rank-up replaces it and origin is gone for good
(`ShouldOfferOrigin` only re-fires while `Epithet == ""`). Concretely: join,
let `checkOrigin` store the origin choice, then run `.magoi 300` (the exact
command in the M4-01 spec and M4-03's playtest script) before answering -
`AddMagoi` fires a second `RankUp` for Wanderer (alignment still White, so
`pick3` falls back to the `GoldBlack` bank) and the Street Rat epithet never
comes back this life. Same overwrite means one big `Magoi` grant crossing
two thresholds only announces the final rank, skipping every intermediate
epithet - relevant once M5 missions grant larger rewards.
Fix: skip announcing while `PendingEpithet ~= nil` (attributes still update
silently); re-check once `ChooseEpithet` clears it.

## Summary for Bryan
Security, schema-migration and attribute-ownership are solid and pass
