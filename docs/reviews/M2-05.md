## Findings

1. **Medium** — `RukhController/init.luau:389-408` (the `HeartAttack`
   handler). Only `playRukhScene` guards against overlap (via
   `sceneGeneration`); `playFatalPulse`/`playNonFatalPulse` have no such
   guard. A second `HeartAttack` fired while a fatal pulse is still
   running (server retry, or a dev firing `.heart fatal` twice quickly)
   starts a second concurrent pulse — two red overlays, doubled
   heartbeat sounds, two "Your heart gave out." labels — violating the
   "a second HeartAttack during a scene doesn't stack" requirement.
   Fix: gate the handler itself (a simple busy flag/generation check
   before starting a new pulse), not just the scene.

2. **Medium** — same handler, plus `playFatalPulse`/`playNonFatalPulse`
   (lines 84-143). These aren't wired into the generation/cleanup system
   `playRukhScene` uses. If the character respawns mid-pulse (before
   `playRukhScene` starts) — e.g. a dev/character reset during the heart
   attack — the pulse's `task.wait`/tween keep running in the background:
   the heartbeat sound keeps playing and "Your heart gave out." can
   appear over the player's new life, instead of being torn down on the
   next `CharacterAdded` as the spec requires for a mid-scene respawn.
   Fix: check the same generation counter inside the pulse loops (or
   destroy the pulse gui/sound from the `CharacterAdded` handler).

3. **Low** — `playHeartbeatSound` (line 42-51) destroys the Sound only
   via `Sound.Ended`; if `Config.Sfx.Heartbeat`'s placeholder asset ever
   fails to load, `Ended` never fires and the Sound leaks under
   `SoundService`. Minor now, worth a `task.delay` fallback destroy.

4. **Note, not blocking** — with the `AfterLife` model present, the
   original `WipeHandlerPart2` also sets `camera.CameraSubject =
   afterlife.AfterlifeCamera`; the port only sets `camera.CFrame`
   (line 315). Harmless under `Scriptable`, but worth matching for
   parity.
