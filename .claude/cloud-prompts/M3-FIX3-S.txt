## Bryan's design (2026-09-28), replaces the current "one Attack = one server-timed swing":
One click = one fist animation containing TWO punches (right, then left). The animation has events (markers): a wind-up and a hit for each punch. The client fires one hit report per hit marker. During a wind-up, if the attacker gets hit, the attack is interrupted and stops. If not interrupted, the punch lands. Right-click cancels the attack ONLY before the first wind-up marker; after that it must carry through. A cancel briefly highlights the player so the enemy can see it (the old "Cancel" highlight). The server stays authoritative: it validates every report and does the hit geometry itself.

## Server changes (`CombatService`, `StatusService` untouched unless needed)
1. `AttackStart` from an owner: same gating as today (alive, not stunned/knocked/true-stunned/blocking, `NextAttackAt` passed, no attack in progress). Creates `attack = {startedAt = now, nextPunch = 1, set, cancelled = false}`, sets `Attacking = true`, broadcasts `Swing`. Schedules a watchdog: if the final punch hasn't been reported by `punches[#].hitWindow.max + tolerance + timeout`, end the attack silently (client desync) and set `NextAttackAt`.
2. `AttackHit(index)`: accept only if an attack is in progress, `index == attack.nextPunch`, `elapsed` inside that punch's `hitWindow` (+/- tolerance), the attacker still valid (alive, not stunned/knocked/true-stunned/blocking, not cancelled), and the anti-teleport check (position at Swing vs now, as today). Then the hit check exactly as today (closest registered target in the sphere ahead, facing, line of sight) and `ApplyHit` with that punch's numbers. `nextPunch += 1`; after the last punch: `Attacking = false`, `NextAttackAt = now + recovery`. Out-of-order, early, late or duplicate reports are dropped with a throttled Warn and count as nothing.
3. **Interrupt:** in `ApplyHit`, when the TARGET has an attack in progress whose next punch hasn't landed, cancel it: `Attacking = false`, `AttackCancelled {character = target, reason = "interrupted"}`, `NextAttackAt = now + that punch's stun`. Also cancel on any Stun/TrueStun/Knocked status turning on (onStatusChanged) and on death/unregister.
4. **Cancel:** `AttackCancel()` accepted only if an attack is in progress, punch 1 not yet landed, and `elapsed <= set.cancelWindow + tolerance`: cancel, `AttackCancelled {reason = "cancelled"}`, `NextAttackAt = now + cancelRecovery`. Otherwise drop with a throttled Warn.
5. **NPCs:** `CombatService.Attack(character)` (used by NpcService) runs the same sequence on server timers: it schedules `AttackHit` internally at the middle of each punch's hitWindow, so NPC punches go through the identical validation and can be interrupted the same way.
6. `.combat log on` prints every decision with `elapsed` in seconds (`AttackStart`, each `AttackHit` accepted/dropped and why, cancels, interrupts) so Bryan can tune the windows to his animation.
